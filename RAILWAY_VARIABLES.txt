SECTION D: CUSTOMIZE YOUR VALUES
================================================================================

Replace these values with your actual configuration:

1. BOT_USER & BOT_PASSWORD
   - Your main bot's username and password
   - Get from Bondage Club game

2. BOT_USER2 & BOT_PASSWORD2 (optional)
   - Secondary bot account (shower narrator in Veratown)
   - Only needed if you want shower narration feature
   - Leave empty to disable

3. BOT_USER3 & BOT_PASSWORD3 (optional)
   - Tertiary bot account (casino in Veratown)
   - Only needed if you want dedicated casino bot
   - Leave empty to disable

4. MONGODB_URI
   - Your MongoDB Atlas connection string
   - Format: mongodb+srv://USERNAME:PASSWORD@CLUSTER.mongodb.net/DATABASE
   - Get from: MongoDB Atlas → Cluster → Connect → Connection String

5. ROOM_NAME & ROOM_DESCRIPTION
   - Display name and description of your BC room
   - ROOM_DESCRIPTION can include \n for line breaks

6. SUPERUSERS, MEMBERS, ROOM_ADMIN
   - Member numbers as JSON array: [250927, 254890]
   - One member per number
   - Find your member number in BC profile

SECTION F: HOW TO GET YOUR VALUES
================================================================================

1. MongoDB URI
   - Log in to mongodb.org/atlas
   - Go to your cluster
   - Click "Connect"
   - Select "Drivers"
   - Copy the connection string
   - It looks like: mongodb+srv://USERNAME:PASSWORD@CLUSTER.mongodb.net/DATABASE

2. Bot Credentials
   - Log into Bondage Club at www.bondageprojects.elementfx.com
   - Create bot character(s)
   - Use character name as BOT_USER
   - Use character password as BOT_PASSWORD

3. Member Numbers
   - In Bondage Club, click on a player
   - Their member number shows in the profile
   - Use in arrays: [250927, 251024]

4. Room Name
   - This is the display name of your BC room
   - Can be anything you want
   - Default: Veratown

================================================================================
SECTION H: IMPORTANT NOTES
================================================================================

✅ DO:
- Use environment variables for sensitive data (passwords)
- Store passwords in Railway secrets (not visible in logs)
- Use JSON array format for member lists: [250927, 254890]
- Set MONGODB_TLS=true for MongoDB Atlas
- Keep ROOM_LIMIT reasonable (20-50 recommended)

❌ DON'T:
- Hardcode passwords in git
- Use special characters in MONGODB_URI (URL encode if needed)
- Leave brackets empty in arrays: use [250927] not []
- Mix old config.json AND environment variables (env vars override)

⚠️ ARRAYS:
- SUPERUSERS, MEMBERS, ROOM_ADMIN must be JSON arrays
- Correct: [250927,254890]
- Correct: [250927, 254890]
- Wrong: 250927,254890
- Wrong: [250927] [254890]

================================================================================
SECTION I: TROUBLESHOOTING
================================================================================

Bot not starting?
→ Check logs in Railway → Deployments → View Logs
→ Look for [Config] messages
→ Verify MONGODB_URI is correct
→ Verify BOT_USER and BOT_PASSWORD are set

Bot connects but doesn't respond?
→ Check BOT_GAME is set to "veratown"
→ Verify ROOM_ADMIN includes the bot's account number

Configuration not applying?
→ Make sure you're in "Raw Editor" mode
→ Click "Save" after pasting variables
→ Wait for Railway to restart (watch Deployments tab)
→ Check logs show [Config] messages

MongoDB connection error?
→ Verify MONGODB_URI is correct (copy from Atlas)
→ Check IP whitelist in MongoDB Atlas (add 0.0.0.0/0)
→ Verify MONGODB_TLS=true for Atlas
